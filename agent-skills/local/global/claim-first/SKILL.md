# 先亮主张（claim-first）

先给主张，再给边界。段首写这段在说什么、证据是什么。

## 边界

适用：论文、基金申请、技术方案、SOP、报告、产品与政策文本的起草和修订。任务结果的书面交付物（汇报、报告、PRD）适用本技能；Agent 的日常对话回复不适用，那些用 `ste`。

通用中文表达清理（空话、模板句）用 `humanizer-zh`。代码、注释、commit message 不在本技能范围内。

## 底线

改写只动措辞和结构，不动事实。六条不让步：

1. **不造事实。** 数据、基线、机制、因果关系、优势只来自原稿或用户。需要新证据才成立的句子，缩小主张，或标为待补。
2. **相关不写成因果。** 观察性关联保持关联。
3. **必要限定保留一次。** 影响主张成立、证据解读、适用范围、研究设计或读者正确使用的限定，写在方法、讨论或局限。
4. **示例只给写法。** 示例里的数字与结论不进入用户文本。
5. **不造计划。** 原稿没有的补做实验、后续版本、承诺时间不得写进改写稿。缺口写成「尚未评估」，不写成「将补充」。
6. **清过期标识符。** 改名、改路径、改版本后，旧名不再出现在改写稿里。报告里的文件名、路径、命令与当前状态一致。

## 论文分支

论文、基金申请、rebuttal 另外读 [论文叙事与实验](references/narrative.md)。

一句话：论文是一场学术发布会，不是项目总结。只围绕最强优势组织，主张与证据一致优先于比较项数量。

## 判据

一句话该不该留，看它是否增加证据、范围、逻辑、概念精度或读者指导。按功能分六类，只删第一类和第六类：

| 类别 | 处理 |
|---|---|
| 不必要的免责 | 删 |
| 必要的范围条件 | 改成陈述式范围 |
| 真实的方法局限 | 保留一次，归位 |
| 有用的概念对比 | 保留 |
| 证据支持的限定 | 保留 |
| 重复澄清 | 删 |

## 执行步骤

### 1. 定主线

用一句话写出主张，并列出支撑它的证据。写不出这句话的内容不进主线。

完成标准：一句话主张在手，每个进入正文的段落都能指向它的某一部分。

### 2. 分类每句

逐句标六类之一。标不出的句子，是还没想清功能的句子。

完成标准：没有未分类句。

### 3. 删免责，写正向范围

删除不提供信息的免责、道歉式铺垫、防御性否定。「本文并不声称覆盖所有情境」改成「本文分析 2015–2023 年三种制度环境下的案例」。

完成标准：删掉的句子都只防质疑、不增信息；每个范围写成陈述式，或明确保留为限定。

### 4. 校准不确定性

保留词指向具体设计边界。删叠加模态，留一个，或换成条件句。

完成标准：每个保留词都能回答「不确定来自哪里」；同一句不超过一个模态词。

### 5. 归位限定

必要限定集中到方法、讨论或局限。摘要、引言、贡献段、段首句、结论各出现一次即可。

完成标准：同一限定在全文不超过两处，且不在摘要与结论重复。

### 6. 交稿自查

逐条回答，每条给出结论。

- 这句话扩大了本文要承担的责任吗？
- 提出了没人要求回答的问题吗？
- 把局部现象写成了普遍缺陷吗？
- 负面判断比证据更宽吗？
- 补做实验、后续版本这类原稿没有的承诺出现了吗？
- 旧名、旧路径、旧版本号还留在改写稿里吗？

改稿有可对照的原文与目标案例时，运行 `scripts/check_rewrite.py` 核对不变量：保留的事实是否还在，防御句式是否已删，数字是否一个不多一个不少。

```bash
python3 scripts/check_rewrite.py --case <id> --rewrite <改写稿路径>
```

完成标准：六条都有结论；有问题的句子已改，或已列入待补。运行了检查器时，退出码为 0，或每条违规都已处理。

## 规则

### 语言

- **先观点。** 段首写结论，限定放段中或段末。
- **一段一件事。** 论证、限定、例外、澄清分开。
- **对比只在对比本身是论证时用。**「不是 X，而是 Y」「与其说…不如说…」是修辞时删。
- **用证据加强，不用形容词加强。** 主张太宽就缩范围、补概念、理顺推理；不追加「当然也存在局限」。
- **具体动词。**「进行测量」「进行温度的测量」「对样品进行温度测量」都写「测量样品温度」。「标定」「解耦」「淬灭」只在确实是那个操作时用。

### 指标与不利结果

同时给出两个数，让读者判断权衡。

> 该方法把延迟从 100 ms 降到 60 ms，准确率 89%，基线 90%。

不写「准确率较低，说明方法仍有局限」。

不利结果的处理顺序：

1. 判断它是否影响核心结论或读者理解。影响就讨论。
2. 写清条件、指标、结果。原因不明就不编解释。
3. 检查是否过宽。证据只支持部分情况就缩范围，完全不支持就撤回。
4. 检查是否把局部现象写成了普遍缺陷。
5. 限定放到相关章节。摘要或结论缺了它会被误解时保留。

可以换比较口径，前提是新口径由研究问题决定，且原口径的结果仍可查。用新口径掩盖已知结果属于改写事实。

### 中文技术文本

方案、SOP、报告的规则见 [技术方案与 SOP](references/technical-sop.md)：含糊前提落成具体条件、缺失信息或删除该动作；说教语气删，禁止事项留。

### 中英模式

中文看习惯性谦辞（仅仅、只能、仍有很大提升空间）。英文看叠加保留词（may potentially suggest）与「not X but Y」。

`may`、`suggest`、`under these conditions` 按证据判断，不机械删。

正反例见 [模式对照](references/patterns.md)。

带不变量断言的改写样例见 [案例集](examples/cases.json)。
