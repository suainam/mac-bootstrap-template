# PRD 评分优化（ai-devops 原型工作台）

目标：以最少、可核验的修改解决真实问题并达到用户约定分数；评分是评审线索，需求事实与用户决定才是业务依据。已达目标且用户已评审通过时停止追分。先读 `references/lessons.md`（已验证踩坑）与该 Story 的 `references/case-*.md`（若存在）。

## 操作流程

1. **锁定基线**：读取目标 Story 当前正文及完整问题清单，记录 `story_code`、正文版本、`prd_id`、与该版本对应的 `module_id`、分数、阻断/重要项及可回退版本。版本回退可能生成新的版本和模块 ID，按实际版本卡或 PRD 元数据重新绑定；不要用旧模块的评分代表新版本。数据定位见 `references/lessons.md` 的「数据定位（React fiber）」。推荐 `scripts/prd_iterate.mjs snapshot <Story-XXXXXX>`：一次性落盘基线正文（回退点）、完整评分、`module_id`、原始需求事实源。
2. **逐项核对**：完整列出问题及建议。先处理阻断、重要项；按一致性、完整性、可验证性、清晰度和风险检查具体影响。识别涉及同一规则的重复问题，合并为一次修订。对照原始需求、已确认口径和当前正文；评分建议不证明业务规则、接口或系统能力存在。缺少会影响行为的业务决定时，先与用户确认，或明确标注待确认，不为提分虚构。
3. **定点修订**：列出每项的章节、原句、最简替换句；同一规则只在一处定义，其余引用。相关状态、公式、例外和验收必须一致。只修改已识别的问题及为消除冲突必须同步的引用；未点名内容保持原样。页面 AI 生成时明确替换范围并要求保留其他内容；用户指定直接编辑时遵从用户选择。
4. **保存前核对**：比对修改前后正文，确认旧冲突句已消除、无无关改动、无未确认事实冒充确定事实。记录修订前内容和回退点；已有高分版本不得在未经用户授权的情况下直接覆盖或丢失。
5. **回读并评分**：保存后回读实际持久化正文，核对目标版本、正文内容及对应 `module_id`，再调用评分。遇到对象存储缓存时，约 35 秒可作为初次等待经验，不作为缓存已失效的证明；比较回读内容或版本标识，评分结果与预期内容不符时排查缓存和模块绑定。不要在浏览器扩展内长时间 sleep。
6. **比较与止损**：比较分数、阻断/重要项和业务正确性；分数未升不等于未修复，问题减少也不等于质量已改善。若降分、新增阻断或出现无关改动，保留或恢复已核验的较优版本，再讨论真正未解决的事项。用户确认评审通过后停止迭代。

**迭代闭环**：评分器严格且每次重算会触发新一轮问题；达标流程为「保存→等缓存(约45s)→重算→读全量issues→再修→循环」。工具：`scripts/prd_iterate.mjs <snapshot|save|rescore> <Story-XXXXXX>`——`save` 直写+精确回读+自动退出编辑并 reload；`rescore` 等缓存、触发重算、按 `score.create_time` 变新才判为新分。工具坑（eval 只解析 JSON 对象 / 正则 flags / 编辑器退出时序 / v13ScoreState 干扰项）见 `references/lessons.md`。

## 评分接口与现有工具

- 问题清单与重算：`POST /api/product-agent/analysis/score/d1d5/recalculate`，body 为 `{story_code, module_id, created_by}`。记录返回的 `final_score`、维度、`issues` 的严重级别、问题、建议和证据位置；响应结构以实际返回为准。
- 正文保存：`POST /api/product-agent/prd/save`，按当前平台契约提供 `prd_id`、`content`、`created_by`、`version`；保存成功后仍需回读及核对。
- 优先复用 `~/.agents/skills/huashu-jev-automation/scripts/prd_workbench.mjs` 与 `scripts/prd_iterate.mjs`；先核实当前平台行为，不假定脚本接口、缓存行为或评分器规则永远不变。
- 页面检测对标题格式可能敏感，如 `量化目标（baseline→target）`、`边界场景（edge_cases）`；检查功能清单和详细说明是否一一对应。仅补充与本需求相关且有依据的内容。修订手法与事实边界见 `references/lessons.md` 的「修订手法」「事实源（grounded）」；完整案例见 `references/case-Story-295628.md`。

## 自动化边界

优先复用现有工具；重复操作确有成本时，先做只读辅助：展示版本与模块映射、完整问题清单、改前改后差异和旧句残留。自动重写不得代替业务判断；写回须遵守用户授权，保留可审阅差异与回退点。只有现有工具经验证不足、且多用户或高频交互确需页面入口时，再评估浏览器插件。
