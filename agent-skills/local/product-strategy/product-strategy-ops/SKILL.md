# 专题作业

1. 确认当前仓库根目录，读取 `CLAUDE.md`、目标专题现有的 `README.md`、`manifest.jsonc` 和更近的 `AGENTS.md`。旧目录缺少根 README/manifest 时，按场景索引进入实际工作目录，沿用其索引与规则，不为调用补造元数据；仓库索引维护只需根目录说明。记录专题、业务日期、输入来源、交付路径及本次是否允许远端写入，不适用的字段标注不适用。完成条件：适用字段有来源；缺少影响执行的字段时先询问。
2. 按 [场景索引](references/scenarios.md) 选择已有入口，只读取命中场景的说明和脚本参数。完成条件：确定工作目录、命令、依赖、输出及副作用；源码用于确认实际行为，业务口径以已确认的专题规则为准，两者冲突时阻断受影响的执行并指出差异。
3. 先读入口确认帮助或预览不会在导入、参数解析前触发业务操作，再执行核对参数，随后运行授权范围内的作业。所有 shell 命令加 `rtk` 前缀。云端补数、DDL、覆盖分区必须有明确目标与日期授权；分析请求默认只读。完成条件：保存命令及退出状态；异步任务保存实例 ID 并查询终态，提交成功不算完成。
4. 按场景核验结果：抽数核对分区、行数和关键汇总；报告核对日期、范围及实际输出文件；索引运行 `--check`。完成条件：所请求的每项输出都有证据，失败与跳过单列。返回产物路径、验证结果和残余工作区变更。

数据路径取 `manifest.jsonc.data_root`，大数据与缓存使用其对应子目录；无 manifest 的旧专题沿用当地批次索引和已确认的数据路径，路径失效时报告缺失，不猜新路径。专题规则和参数保留在原 README/脚本中；这里仅维护入口选择。
