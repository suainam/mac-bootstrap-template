# 企业门户协同反模式与避坑指南 (Anti-Patterns)

本文件归纳在四大企业门户（HPM 绩效、DevOps 效能、Confluence Wiki、商品决策）自动化操作与填报时必须规避的 5 种典型反模式。

---

## 反模式 1：Vue 双向绑定失效（静默空值提交）

- **问题**：在 Element-UI 输入框直接执行 `input.value = "新内容"` 后立即点击保存。
- **后果**：DOM 视觉上填入了文字，但 Vue 内部的 `v-model` 数据并没有被触发更新。点击保存后，前端发送给后端的 Payload 依然是空值或旧值，导致数据静默丢失。
- **正确规范 (`v-model-sync`)**：必须派发 `input` 与 `change` 冒泡事件：
  ```javascript
  input.value = val;
  input.dispatchEvent(new Event('input', { bubbles: true }));
  input.dispatchEvent(new Event('change', { bubbles: true }));
  ```

---

## 反模式 2：越权点击【提交】（破坏人工终审红线）

- **问题**：在 HPM 绩效填报或 DevOps 审批流程中，脚本直接定位并点击【提交审批】或【最终发布】按钮。
- **后果**：剥夺了员工本人的最终审核权。一旦存在未核实的数据或错别字，流程进入审批链路后无法直接撤回，产生合规事故。
- **正确规范 (`draft-only`)**：
  - HPM 场景脚本严格锁定 `button:has-text("保存")`，禁止任何含有“提交”关键字的定位器。
  - DevOps 场景工时严格点击【暂存】或【保存】，每周五由本人手动提交。

---

## 反模式 3：冗余的档位前缀与 AI 空洞辞藻

- **问题**：
  - 绩效文本开头生硬添加“1档（系数：1）”前缀；
  - 充斥“全方位赋能、构筑坚实基石、多点开花、立体升维”等虚浮套话，但无具体业务动作和证据。
- **正确规范 (`grounded` & `no-prefix`)**：
  - 删除所有前缀，直接输出纯事实。
  - 所有数据必须来自 `product_strategy` 仓库中可追溯的指标（如动销率 +1.66%、库存成本降 984.78 万元）。

---

## 反模式 4：脱离 Git 凭据虚构工时 (Unverified Timesheet)

- **问题**：在 DevOps 工时日历中，为了填满 40 小时，随意挂接无交付物的需求，或在休假日填报工时。
- **后果**：效能平台会将工时与 Git Commit、代码行数及需求进度交叉对齐，虚构工时会在月末效能审计中被判定为异常。
- **正确规范 (`timesheet-audit`)**：
  - 填报工时前，检索本地当周 `git log --author=suai --since="7 days ago"`，提取实际参与的分支与需求号。
  - 工时填报严格与代码提交和数仓任务对应。

---

## 反模式 5：Wiki 破坏性覆盖 (Destructive Wiki Overwrite)

- **问题**：在更新 Confluence Wiki 时，直接将整个文档正文替换为简短的 Markdown 摘要，冲掉原有的架构图、历史附件或上下游关联链接。
- **后果**：团队沉淀的多版本结构被覆盖破坏，需要管理员进入 Page History 紧急回滚。
- **正确规范 (`wiki-sync`)**：
  - 采用**定点追加或章节更新**策略：定位具体的二级标题（如“版本修订记录”或“最新策略说明”），仅对增量部分进行插入或替换。
