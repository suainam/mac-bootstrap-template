# 数据质量门禁清单 (Data Quality Checklist)

在基于 ODPS 和 Python 开展任何专题分析或交付输出前，必须逐项执行以下质量防线核对。

---

## 1. 实体粒度与主键约束 (Grain & Uniqueness)

| 检查项 | 验证 SQL / 代码 | 合格标准 |
| :--- | :--- | :--- |
| **单表主键唯一性** | `SELECT COUNT(1) - COUNT(DISTINCT keys) FROM table WHERE pt = <target_pt>` | 严格等于 `0` |
| **多版本并发去重** | 检查是否存在 `version_id` / `version_num` 多版本 | 关联前必须用 CTE `GROUP BY` 收敛 |
| **维表放大防护** | `dim_store` / `dim_item_master` 主键去重 | 关联键在锁定分区内重复数为 `0` |

### 聚合与去重铁律 (Aggregation vs. Deduplication Discipline)
1. **严禁无脑 `GROUP BY + MAX()` 压重**：必须先实测底表真实粒度与重复行根因。维表在实测目标分区内若已严格唯一（0 重复），绝不使用 `MAX()` 压重，避免静默丢弃多值或掩盖底层错数。
2. **仅保留三类语义必需聚合**：
   - 跨月/跨期时间窗口聚合；
   - 多渠道横向转列聚合；
   - 存在性集合判定聚合（如 `COLLECT_SET`）。

---

## 2. 分区、快照与过滤合法性 (Partition & Filter Gates)

1. **实测分区与基准快照锁定**：基于底表物理特性（实测分区分布、数据就绪日、是否存在停更或未上线区域）显式指定目标分区/日期；**严禁未经探查盲目一律使用 `MAX_PT`**（防止命中断更旧分区、测试脏分区或未来空分区）。
2. **过滤条件守恒断言**：在应用业务过滤前后，记录行数与关键维度的覆盖比例，不可出现断崖式未预期漏斗。
3. **NULL / 空白 / 关联未命中 / 0 / 负值严格区分**：
   - **缺失不是 0**：`NULL` 销量或关联未命中是“未知/待核验状态”，**严禁无条件使用 `COALESCE(sales, 0)` 默认补 0 当作“无销”**，否则会导致保护标签失效或误触发剔除；
   - **0 与负值（退货）显式契约**：`= 0` 与 `<= 0`（含冲减/退货流水）必须由业务契约显式决定，禁止代码隐式推演；
   - **防卫探针**：字符串判空使用 `(col IS NULL OR TRIM(col) = '')`，避免逻辑被 `NULL` 静默吞噬。

---

## 3. 目录增删、清洗与剔除 5 大工程铁律 (Assortment & Catalog Filtering Rules)

在商品/门店目录增删、清洗、剔除及多源判定任务中，必须严格遵守以下 5 项铁律：

1. **正向收紧判定，严禁 ELSE 兜底**：
   - 业务动作中“剔除”具高破坏性，“保留”为基准态；
   - 剔除判定必须是全部要素同时为 TRUE 的严密白名单交集；
   - 保留原因必须显式逐级分流，末尾的 `ELSE` 只能作为防卫探针且命中数必须等于 0。靠 `ELSE` 兜底会导致未预期的 NULL 或脏数据全部静默误判。
2. **禁止擅自篡改业务条件**：
   - 严禁分析师在未获业务明确授权下擅自把“金额=0”混入剔除判定；
   - NULL 销量/标签补 0 会诱发误剔除；`=0` 与 `<=0` 由明确契约决定。
3. **动作标记计算一次，原因消费标记**：
   - 动作标记（如 `is_drop`）必须是一次性正向判定的确定性布尔值；
   - 原因字段（`drop_reason` / `retain_reason`）直接消费该标记派生；
   - 标记与原因必须 100% 互斥闭环：标记为 0（保留）时原因严禁为剔除，反之亦然（杜绝 `is_drop_v2=0` 却标注剔除原因的严重口径事故）。
4. **口径与字段同源单点取值**：
   - 展示字段与计算判定字段必须取自同一计算节点与别名，严禁“判定取表 A、展示取表 B”；
   - 若底层下发表属性缺失，必须在 Layer 1 前置清洗层统一下沉关联主数据权威源补齐后再行判定与展示。
5. **业务保护不穿透与对账守恒**：
   - 业务保护标签（战略品/重点品/指定保护）优先级最高，绝不可被后续规则穿透误剔；
   - 主键集合守恒：输入主键集合 = 剔除集合 + 保留集合（交集为 0，并集等于全集）；
   - 金额与数量按适用契约守恒，无未预期泄漏。

---

## 4. 跨表 Join 守恒断言 (Join Conservation)

- **Left Join 膨胀门禁**：`Left Join` 后的行数必须精确等于主表过滤后的行数。若行数增加，说明右表主键不唯一，必须停止并报警。
- **Inner Join 漏损门禁**：记录未匹配上的孤儿记录数量（`COUNT(CASE WHEN r.key IS NULL ...)`），占比超过 1% 需给出业务归因。

---

## 5. 交付文件格式与仓湖隔离规范 (Delivery Quality & Lake Isolation)

- **仓湖严格物理隔离**：全量二进制数据（Parquet/Excel/CSV 物理实体）必须且只能存入外部数据湖目录，**严禁依据行数（如 100 万行）判定是否外置**。Git 仓库内仅保留相对软链接与 Markdown 文本报告，严禁将物理二进制文件写进 git。
- **交付资产稳定命名与同名幂等覆盖**：同一份数据交付物必须坚持稳定命名，禁止衍生 `_v1`/`_v2`/`_fixed` 等多余名字造成下游混乱；迭代更新必须先生成临时产物，通过确定性门禁验证后，同名原子覆盖物理实体并校验软链接。
- **CSV 规范**：统一带 UTF-8 BOM（Python 中为 `encoding='utf-8-sig'`），确保跨平台打开不乱码。
- **Excel 规范**：使用 `openpyxl` 引擎，必须包含表头冻结与标准中文列名。
- **脚本列名解耦契约**：数据聚合与中间字典严禁直接使用包含空格或括号的长中文表头作为字典 Key；统一采用清晰的 `snake_case` 英文标识（如 `cancel_lines`、`store_code`），仅在最终 `write_excel` 或渲染映射阶段通过 `COLUMN_MAPPING` 统一转换为中英双语表头，防止表头微调引发 `KeyError`。

---

## 6. 空间与图元尺度有界性断言 (Spatial & Scale Invariants)


在执行可视化制图、布局解析或空间组件渲染时，前置执行以下对抗性几何约束：

1. **绝对物理单位基准**：绘图引擎统一声明物理度量单位（如 $1\text{ unit} == 1\text{ cm}$ 或 $1\text{ unit} == 1\text{ mm}$），坐标计算与图元渲染严格遵循同一比例尺。
2. **字号与图元尺度有界门禁**：文字高度必须受控于容器尺寸（如文字字号 $\le$ 货架厚度的 $35\%$），严禁绝对字号超出实体几何厚度引发文字重叠挤压。
3. **几何多边形无缝与无交断言**：同组同排相邻货架的边缘间距误差 $< 0.1\text{cm}$，不同独立货架矩形闭包交集面积严格为 0。
4. **对抗性自动化用例固化**：脚本产出后必须配套执行对抗性审查测试（Adversarial Test），覆盖列名唯一性、图元上界与分类映射完整性。
5. **物理空间密度常识断言 (Physical Density Sanity Check)**：涉及门店物理货架、展架、设备等空间指标时，计算空间承载密度比值（如 $\frac{\text{门店陈列架总长度 (米)}}{\text{门店营业面积 (m²)}}$）。正常经营药店/便利店该比值处于 $[0.4, 1.8]$ 区间；低于 0.3 说明存在严重漏登或型号误折叠，高于 2.0 说明存在跨品类重复混陈双计，必须触发阻断审查。
