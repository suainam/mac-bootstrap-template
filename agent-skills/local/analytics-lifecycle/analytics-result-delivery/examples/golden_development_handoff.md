## 二、标准章节脉络与核心要求

### 一、问题背景与需求范围
1. **1.1 核心痛点与历史缺陷**：直接点出生产节点 ID、物理表名与行号。给出原 SQL 片段并说明数理根因（如开窗缺少分区键、标签硬编码、版本串味等），明确业务影响。生产前置链路已有规则（如销售端已剔除仓储异常）据实陈述，不在交接中重复提出非生产改造诉求。
2. **1.2 需求边界与子需求隔离**：明确本需求限定范围（`scope_type`）、与其他子需求（如 a/b 拆分）的隔离边界以及当前推进状态。

### 二、现有生产节点资产画像与上下游拓扑
1. **生产现实画像表**：必须列出 DataWorks 节点 ID、节点全称、所属工作流/Baseline、调度周期/Cron、环境（PROD）、调度参数配置（`ParamValues`）、目标物理产出表、分区规范及仓库源码镜像路径。
2. **上下游 Mermaid 拓扑图**：自顶向下绘制 `[上游数据输入] --> [核心改造节点] --> [下游消费链路]`，清晰标注各表的过滤与字段传递关系。

### 三、生产改造点与 SQL 实施路径
1. **对比呈现代码**：分位置列出【原始生产代码】与【改造后标准代码】。
2. **补充稳定性 tie-break 键**：若涉及开窗排重，必须在 `ORDER BY` 末尾补充 `item_code ASC` 等确定性单品键，彻底消除并列漂移。
3. **最外层提取收敛**：明确业务决策选定的推荐档位（如 `WHERE rn = 1 AND ...`）。
4. **下游防污染改造**：明确下游节点所需的版本过滤（`AND version_id = '${version_id}'`）。

### 四、键契约、排序、去重、版本与 NULL 契约
使用规范五栏表格锁定：
- **主键契约**：`(store_code, item_code)` 严格唯一无重复；
- **选码排重契约**：每店每缺口只补 1 个最优品（`rn = 1`）；
- **排序稳定性契约**：确定性排序列；
- **版本与配置契约**：明确 `scope_type` 与 `version_id` 消费控制；
- **NULL 契约**：缺失事实严格保留 NULL，不伪填 0.0，主推等级平滑过滤。

### 五、接口字段契约 (Schema Contract)
给出目标生产表的完整 DDL 字段字典表格：物理字段名、字段类型、字段中文含义、空值约束（`NOT NULL` / `NULLABLE`）及业务计算规则。

### 六、技术逐项验收标准 (Acceptance Criteria)
提供产研团队在预发/测试调度中必须执行的回归验收 SQL 查询（直接可执行）：
- **用例 1：主键唯一性与零跨店跳跃**（`HAVING COUNT(1) > 1` 预期 0 行）；
- **用例 2：单店单品规排重校验**；
- **用例 3：下游节点版本隔离校验**（`unversioned_cnt == 0`）。

### 七、发布与回滚方案
1. **7.1 发布方案**：预发历史分区回放规模对账、首日调度监控指标。
2. **7.2 回滚方案**：明确 SQL 逻辑回退版本号与历史代码重刷机制。
