# HPM 考核标准与指标规则

## 1. 评分档位与分值对照

HPM 系统对定量指标与定性指标采用统一档位换算机制：

| 档位名称 | 折算系数 | 适用场景 | 目标要求 |
|---|---|---|---|
| **1.25档** | 1.25 | OKR 突破类指标最高档 | 远超预期目标，业务效果呈现翻倍或数倍达成 |
| **1.2档** | 1.20 | OKR 突破类指标次高档 | 超额完成目标，业务表现优异 |
| **1.1档** | 1.10 | OKR 突破类指标高档 | 超出既定指标，提前保质交付 |
| **1档** | 1.00 | 常规指标满分 / 定性指标满档 | 100% 达成既定关键任务，符合全部完成标志 |
| **0.9档** | 0.90 | 基本达成 | 核心任务达成，个别次要点有轻微延误或偏差 |
| **0.8档** | 0.80 | 部分达成 | 任务交付但业务效果不达预期 |
| **0.7档及以下** | $\le 0.70$ | 未达成 / 故障延期 | 出现低级错误、P0/P1故障或严重延期 |

> **注**：自评总分公式为 $\sum (\text{指标权重} \times \text{指标得分})$。通常将突破类自评置为 1.25，常规类与定性类置为 1.0，整体自评合理区间在 1.05 ~ 1.10 之间。

## 2. 通用力指标官方考核要点 (3.1 ~ 3.6)

每项通用力权重均为 **3%**，满分自评需对标以下官方完成标志：

### 3.1 专业知识/技能 (定性 3%)
- **零低级错误**：季度内无因个人疏忽/技能导致的返工、P0/P1级故障或项目延期。
- **知识沉淀**：主动输出 $\ge 1$ 份高质量工作文档（P3 及以下 $\ge 1$ 份，P4 及以上 $\ge 2$ 份），具备复用价值，可在团队内推广落地（如：业务操作指引/复盘/SOP/设计规范等）。

### 3.2 计划/组织/执行/解决问题能力 (定性 3%)
- **承诺必达**：个人负责的任务/节点按期 100% 交付。
- **风险前置**：遇到阻力或延期风险，提前 24 小时预警，并提出至少 1 个备选解决方案。
- **闭环思维**：所有任务状态清晰，事事有回音，主动追踪结果并同步上级/项目组成员。

### 3.3 沟通与团队协作能力 (定性 3%)
- **响应及时**：工作时间内，对同事/业务方的咨询，4 小时内给予实质性回复。
- **有效发声**：在评审/会议中，至少提出 $\ge 1$ 条建设性意见。
- **零有效投诉**：季度内无因态度、推诿扯皮收到的投诉。

### 3.4 学习与发展能力 (定性 3%)
- **学以致用**：季度内主动学习并应用 $\ge 1$ 项新技能/新工具/新方法到实际工作中（需体现效率提升或质量改善）。
- **学习互动**：P4 以上支持/指导他人解决问题 $\ge 2$ 次；初级员工主动请教/复盘 $\ge 3$ 次。
- **复盘改进**：针对工作中的不足或故障，输出 $\ge 1$ 条具体的改进措施并落实。

### 3.5 创新能力 (定性 3%)
- **优化提案**：主动提出 $\ge 1$ 条关于流程、工具、成本或体验的优化建议，并被团队采纳。
- **提效实践**：通过自动化脚本、模板化、标准化等手段，使某项重复性工作效率提升 $\ge 10\%$（或有明显工时节省）。

### 3.6 专业影响力 (定性 3%)
- **技能分享**：在组内或跨组进行 $\ge 1$ 次专业知识分享或案例讲解。
- **知识贡献**：向团队知识库贡献 $\ge 2$ 篇高价值原创内容（含实战总结、避坑指南、最佳实践等）。
- **难题攻坚**：主导或核心参与解决 $\ge 1$ 个跨模块/跨部门的复杂难题或历史遗留问题（P4 及以上 $\ge 2$ 个）。
- **正向辐射**：获得内部同事或外部客户的书面表扬，或在团队中起到积极的“润滑剂”作用。

## 3. 页面填报与技术交互约束

1. **下拉框 vs 文本框**：
   - 下拉框（`.el-select`）用于设置最终档位（如 `1档(系数：1)`），此项决定系统折算分值。
   - 文本框（`textarea` 或弹窗输入）仅用于描述工作产出与事实证据。
   - **绝对不要在文本框中重复录入档位名称**。
2. **只读文本框与弹窗交互机制**：
   - 责任书中的完成说明 `textarea` 设置了 `readonly=""` 属性，直接修改 `.value` 无法生效。
   - 点击该文本框后，Element UI 会在 `body` 根节点挂载 `.el-popper.is-light.el-popover` 弹窗。
   - 必须向弹窗内部的 `textarea` 输入内容，随后点击弹窗底部的【确认】按钮触发数据同步。
3. **字符容量上限**：
   - 所有文本域均有 `0 / 1000` 字符硬门禁。
   - 建议篇幅控制在 150 ~ 750 字区间，避免过短显单薄或过长被浏览器或后端截断。

## 4. 责任书读取路径 (Read Path)

`source-first`：动笔前先读出在线责任书的全部字段。三条路径按可用性依次尝试。

### 4.1 relay 复用已登录 Chrome（首选）

```javascript
const tab = await browser.open({ name: "hpm", app: { relay: true, target: "/achievement" } });
const rows = await tab.run("return await tab.evaluate(() => document.body.innerText);");
```

relay 扩展未连接时报 `omp browser relay is serving at http://127.0.0.1:9224 but its extension never connected`。此时不要重试同一路径，改用 4.2。

### 4.2 剪贴板读取已渲染页面（无需扩展、无需 DevTools 协议）

适用于用户在 Chrome 中已打开并登录该页面的情况。读取的是页面渲染后的可见文本，与人工查看一致。

```bash
osascript <<'EOF'
tell application "Google Chrome"
  repeat with w in windows
    repeat with t in tabs of w
      if (URL of t) contains "hpmEventId=104018" then
        set active tab index of w to (index of t)
        set index of w to 1
      end if
    end repeat
  end repeat
  activate
end tell
EOF
osascript -e 'tell application "System Events" to keystroke "a" using command down' \
         -e 'tell application "System Events" to keystroke "c" using command down'
pbpaste
```

前提与边界：

- 该 Chrome 窗口须能切到前台；全屏或另一应用抢占焦点时，`activate` 后确认 `frontmost` 是本应用再发送按键。
- 复制的是整页可见文本，指标按“序号 / 名称 / 指标类型 / 档位选项 / 指标说明 / 计划时间 / 权重”逐块出现，可直接解析。
- 只读操作，不改动页面状态。
- AppleScript 直接执行 JS（`execute t javascript …`）在“显示 > 开发者 > 允许 Apple 事件中的 JavaScript”关闭时不可用，且该菜单项可能因企业策略置灰；剪贴板路径不依赖它。

### 4.3 agent-browser 只读快照（备用）

```bash
agent-browser --session hpm snapshot -i
```

仅用于确认页面结构与按钮 ref，不解析跨域 iframe 内的业务字段。

### 4.4 内网直连不可行的判定

`xzapp.dslbuy.com` 为内网域名。`curl` 与代理直连可返回 200，但浏览器自动化进程常报 `ERR_NETWORK_ACCESS_DENIED` 或 `ERR_CONNECTION_CLOSED`；遇到这两个错误即改用 4.2，不在代理参数上反复尝试。
