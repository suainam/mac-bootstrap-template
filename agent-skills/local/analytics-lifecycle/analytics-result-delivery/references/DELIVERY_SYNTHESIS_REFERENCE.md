# 阶段五数据分析交付规范与各专题融合指南 (Delivery Synthesis Reference)

本指南对 `template/agent-skills/local/product-strategy/` 下三大成熟专题的交付模式进行取长补短与融合提炼：
1. **`ps-new-store-benefit-report`**：贡献了 32 项标准中文字段体系、多 Sheet 分层工作簿（跟进中 vs 已结束）、严格对抗性质量门禁与单调性校验；
2. **`ps-franchise-store-report`**：贡献了现代前端品味 HTML 看板（基于 `report_style.css` 优雅中性色盘、排版呼吸感与移动响应）、桑基账本平衡流图；
3. **`o2o-store-benefit-report`**：贡献了卡片式诊断架构（多渠道明细 vs 重点店对比）、店均规模量化归因与自动化排版脚本。

## 一、 现代前端品味 HTML 看板设计规约 (`design-taste-frontend` 融合)

在阶段五制作供高管与业务方检视的 HTML 决策看板时，严格遵守以下反模板化与视觉品味准则：

### 1. 字体层级与排版呼吸感 (Typography & Rhythm)
- **字体系统**：优先调用系统无衬线字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`；
- **排版阶梯**：
  - 超大数字强调（KPI Value）：`28px ~ 36px`，`font-weight: 700`，配合微型单位标签；
  - 一级大标题：`20px ~ 24px`，`font-weight: 600`；
  - 模块小标题：`14px ~ 16px`，`font-weight: 600`，带细边框卡片胶囊；
  - 正文字体：`13px ~ 14px`，行高锁定 `1.6 ~ 1.7`，阅读舒适度最高；
  - 辅助注释与数据源标签：`11px ~ 12px`，色值采用中性灰色（如 `#64748b`）。

### 2. 配色系统与中性基调 (Color Consistency)
- **主背景**：浅冷灰 / 温暖纸白微渐变 (`#f8fafc` 至 `#f1f5f9`)，消除纯白对眼睛的生硬刺激；
- **卡片容器**：纯白底 (`#ffffff`)，配以极细微透明边框 (`1px solid rgba(226, 232, 240, 0.8)`) 与柔和弥散阴影 (`box-shadow: 0 4px 20px -2px rgba(15, 23, 42, 0.05)`)；
- **功能强调色**：
  - 目录内 / 优异表现（Primary / Success）：深邃商务蓝 (`#1e40af` / `#0f172a`) 或稳健翠绿 (`#059669`)；
  - 手工品 / 警示缺损（Warning / Accent）：克制温和的琥珀橙 (`#d97706`)；
  - 严重异常 / 下滑（Danger）：低饱和砖红 (`#dc2626`)，严禁使用高饱和荧光红绿。

### 3. “总-分-总”结构叙事标准 (Narrative Layout)
- **顶层（总）**：核心结论卡片（Executive Callout），用 1~2 句话直接道破终局事实与核心定性，附带 3~4 个关键 KPI 统计块；
- **中层（分）**：
  - **过程漏斗**：展示从算法下发 $\to$ 业务审核 $\to$ 到店在营 $\to$ 缺货断流的全链路流转漏斗；
  - **微观品效对决**：目录内 vs 目录外手工的在营数、销售额、动销率、单品日均流水与单品毛利表格对比；
  - **宏观大盘对齐**：目标实体挂载严格同周期的同期新店均线与区域成熟老店均线；
- **底层（总）**：行动闭环建议卡，明确指出供应链保供方向、低效手工品清退策略与筹备期新店前置预防动作。

## 二、 高管级 Excel 工作簿交付规范 (`executive-excel`)

1. **三层金字塔架构**：
   - **Sheet 1 (`Summary`)**：宏观层汇总（重点门店对比矩阵、达成比、核心 KPI）；
   - **Sheet 2 (`Detail`)**：微观层明细（店品粒度或分类明细，保留底层数据支持业务随时下钻）；
   - **Sheet 3 (`Dictionary`)**：字段字典与口径说明（标准中文列名、对应物理字段、计算公式、业务理由）。
2. **格式化工程纪律**：
   - 表头采用深蓝底白字 (`Fill: #1F4E79`, `Font: #FFFFFF`, Bold, 居中对齐)；
   - 所有金额列强制格式化为 `#,##0.00`，数量格式化为 `#,##0`，比率格式化为 `0.00%`；
   - 自动计算列宽（最大长度 + 4，最小 12），严禁出现 `###` 遮挡；
   - 保证无 `#VALUE!`、`#DIV/0!`、`NaN` 等计算脏值。

## 二点五、 交互式决策看板设计规范 (`vector-crisp-dashboard`)

在交付基于 HTML / SVG 的交互式决策看板与空间布局看板时，遵循以下工程标准：

1. **原生 SVG ViewBox 矢量缩放**：平移与缩放逻辑直接基于 `svg.setAttribute('viewBox', ...)`，由浏览器 GPU 实时矢量渲染，保证任意倍数放大下文字与线条绝对无损清晰。
2. **分栏拖拽与弹性自适应 (`resizable-split`)**：看板侧边栏配置原生拖拽分割条（`#resizer`），支持在 $300\text{px} \sim 950\text{px}$ 范围自由调整，兼顾大图查看与清单表格下钻。
3. **业务图例色系收敛归并**：图例位于画面底部横向平铺，按 6~8 大核心业务品类色系统一归并，避免几十个细分碎片图例堆叠遮挡。
4. **双向事件联动选中**：图中图元点击与右侧清单行点击实现双向互锁高亮，并联动触发自动平滑滚动定位。

## 四、 交付成果双模物化与业务用语净化规约 (`dual-delivery-clean`)

### 1. 业务用语去黑话映射词典 (Executive Jargon Purge)

所有呈报高管与业务人员的交付材料（Markdown、HTML 看板、Excel、PPT），禁止堆砌底层技术与工程测绘术语，严格执行如下用语替换：

| 底层工程/测绘用语 | 严禁写法 (Bad Pattern) | 推荐业务化表述 (Best Practice) | 理由说明 |
| :--- | :--- | :--- | :--- |
| **延米** | “门店货架总延米为 54 米” | **“门店陈列架总长度为 54 米”** | “延米”属于工程与装修测绘术语，业务直观感知的是“陈列架总长度”。 |
| **米效** | “米效倒挂 / 算术米效” | **“月均米效 (元/米·月)”** 或 **“每米陈列架产出”** | 明确时间粒度与物理单位，避免日均与月均混淆。 |
| **分母** | “分母虚假膨胀 / 压缩” | **“货架硬件基数 / 统计货架总规模”** | 采用业务可感知的实体规模表述。 |
| **笛卡尔积** | “跨品类 Join 产生笛卡尔积” | **“一架多类混陈重复累计 / 重复双计”** | 还原真实的现场业务场景。 |
| **实体主键** | “store_code 主键粒度” | **“门店编码 / 单店维度”** | 采用零售营运习惯用语。 |
| **度量下钻** | “下钻到营运区维表” | **“按大区、营运区逐级展开”** | 降低管理层阅读理解心智负担。 |

### 2. 双模物化落盘规约 (Dual-Modal Materialization)

每个正式分析交付项必须同时物化产出两套资产：
1. **文本与代码归档**：落盘至 `topics/<topic_id>/05_delivery/md/demand-<ID>-05-delivery.md`，完整记录原始背景、SQL、门禁数据与决策建议；
2. **高管交互看板**：基于 `am render` 工具编译生成独立的单文件 HTML（落盘至 `topics/<topic_id>/05_delivery/demand-<ID>-05-delivery.html`），支持业务方双击直接在浏览器中检视与交互。
