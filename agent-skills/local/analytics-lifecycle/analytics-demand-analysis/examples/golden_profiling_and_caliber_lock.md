## 2. 核心指标算法与业务理由 (Metrics Definitions & Rationales)

| 核心指标项 | 物理字段与算法公式 | 为什么这样计算？（业务与统计学理由） |
| :--- | :--- | :--- |
| **1. 考核期时间窗口** | $s\_kh = end\_dt + 1$ 至 $e\_kh = s\_kh + 90$ | 剔除开业前 5 天大促期间狂卖日化纸品等非稳态干扰，真实反映常规期 90 天自营能力。 |
| **2. 组货目录执行率 (%)** | $\frac{\text{目录内在营商品数}}{\text{全店在营总商品数}} \times 100\%$ | 业务营运强管控导向。二元互斥（在营商品不是目录内就是目录外），真实反映货架终端最终落地事实。 |
| **3. 动销率 (%)** | $\frac{\text{考核期内净销售额 } > 0 \text{ 的在营品项数}}{\text{在营总品项数}} \times 100\%$ | 分母为门店实际在营货架商品，分子为考核期有真实营收贡献的商品。目录内与目录外双轨独立测算。 |
| **4. 真实销售流水** | `SUM(sale_amt)` (100% 真实全额流水) | 本次是“组货商品策略品效评估”，不是“店员绩效考核”，杜绝引入 O2O 1/3 人为折扣，反映客观经营价值。 |
| **5. 截面默认近90天口径** | `lt90_sale_amt_sum`, `lt90_item_sale_cnt_sum` | 数仓组货目录表（`ads_item_store_content_day_stat_sale`）自带近90天聚合，若在考核截止日（9.15）切片，与业务系统统计口径天然吻合。 |

## 5. 阶段三分析方向与设计指引 (Stage 3 Strategic Guidance)

根据前四部分的探索事实与画像，阶段三方案设计应明确**聚焦三大核心分析方向与建模原则**：

### 1. 核心计算基准日选定建议 (Snapshot Date Alignment)
- **目标建议**：结合目标实体周期结束日（如 16472 贺州广场店考核于 2026-09-15 结束），建议阶段三提取组货目录指标时优先使用 `stat_date = 20260915` 截面；
- **业务依据**：数仓底表 `dsl_ads.ads_item_store_content_day_stat_sale` 原生自带 `lt90_sale_amt_sum`，以 9.15 切片，其近 90 天天然覆盖的就是 6.18 ~ 9.15，能与考核窗口对齐，减少非必要的多表跨日开销，且与系统大盘报表口径一致。

### 2. 样本分类与模型适用性矫正 (Sample Categorization)
- 桂林阳朔店（17226）因考核尚未正式开始（10.27 起算），在阶段三方案中不建议将其销售额硬套入考核达成率模型，避免除零或负数等伪统计异常；
- 建议将其专门定义为**“静态备货结构样本 (Assortment Structure Sample)”**，重点对比其在营商品中系统推荐目录与手工自选的品类分布与货架宽度。

### 3. 下一步方案设计目标建议 (Stage 3 Technical Goals)
- **G1 (目录内外效益对比宽表)**：基于基准日截面，输出包含目录内外在营数、动销数、动销率、销售额、销售占比、毛利额的二元互斥宽表；
- **G2 (同期新店基准对齐)**：将目标店的表现挂载至同期开业新店大盘均线与营运区老店均线双重视角；
- **G3 (通用化动态切片扩展)**：方案设计中保持动态日期宏语法，便于后续批次新店按各自考核结束日（$e\_kh$）自适应跑数。
