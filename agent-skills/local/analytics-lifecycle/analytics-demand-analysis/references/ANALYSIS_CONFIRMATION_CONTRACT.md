## 0. 使用规则 (Usage Rules)

1. **每次阶段回复/交付必须显式核对** §1 六栏，不得省略任一栏；未决项不得伪装为已确认。
2. **已确认项不重复索取**：阶段一/二已锁定的粒度、分母、时间窗、对照组直接继承，仅在本阶段新增或变更时重新确认。
3. **技术与业务验证分离**：技术验证（物理表/分区/键/基数/未匹配）由分析师自行查证后呈现；业务验证（指标方向/阈值/策略影响）才需用户确认。严禁向用户索取工具可查的信息。
4. **未决阻断仅依赖部分**：阻断时仅列出**本阶段无法继续的最小未决集**，并说明已可推进的部分；不得把整个阶段挂起。
5. **不通用化特定业务**：上海慢病统筹的 0.5 系数、5 店阈值、主推过滤等仅在对应专题生效，不得写入本契约或技能通用条款。
6. **产物完成前对抗性审查 (Pre-Completion Adversarial Review)**：各阶段产物落盘后、宣布完成前，按 §2.0 通用流程审查一次。这是**技术自查/同行审阅**，不是业务验收，也不是生产上线审批；不得据此要求用户额外确认或补签。
7. **审查不扩权**：审查只读实际产物、当前已确认范围与运行证据；不得把未确认事项、专题阈值或本阶段范围外的假设算作缺陷；不得虚构审查通过——无证据一律写"未验证"。

## 1. 阶段回复与交付六栏 (Six-Column Reply/Delivery Convention)

每个阶段的回复与交付物末尾必须包含以下六栏（Markdown 表格或等价结构）：

| # | 栏目 | 内容要求 |
|---|------|----------|
| 1 | **阶段与交付资产 (Stage & Asset Identity)** | 当前阶段编号与名称（一~五）；上一阶段输入路径；本阶段输出路径及唯一交付资产身份（继承既有稳定文件名，禁止私自衍生 _v1/_v2 等别名；外部数据湖物理路径；仓库入口软链接）。 |
| 2 | **边界与快照 (Boundaries & Snapshots)** | 实体粒度与主键；时间窗口与业务基准日/锁定快照分区（实测物理分区，严禁未探查盲目依赖 MAX_PT）；过滤门禁；主动排除 (Non-Goals)；样本分层（成熟轨 vs 备货轨，仅新店效益分析适用）。 |
| 3 | **重点指标、分母与缺失语义 (Metrics, Denominators & Null Semantics)** | 核心指标分子/分母/公式；字段权威源与展示/判定同源单点取值；NULL/空白/未命中/零值语义区分（NULL 与关联未命中明确为待核验，禁止无条件默认补 0；明确 0 与负数策略）；比率有界区间；分母口径。 |
| 4 | **物理表/分区/键/关联基数/未匹配处置 (Physical & Join Audit)** | 核心事实表/维表全称；分区定位方式（基于表物理特性的实测分区/快照，查证是否存在未上线、断更或脏分区，禁止一律盲目 MAX_PT）；关联键权威源；Join 前后行数；未匹配孤儿记录数与归因处置；多版本收敛方式（仅语义必需才聚合，实测唯一绝不压重）。 |
| 5 | **已确认 / 未决与阻断 (Confirmed / Pending / Blockers)** | 已确认项（继承+新增）；未决项（仅业务影响需用户确认）；阻断项与最小未决集。 |
| 6 | **证据与完成标准 (Evidence & Completion)** | 证据文件/SQL/断言结果；本阶段完成标准逐项勾选。 |

## 2.0 产物完成前对抗性审查通用流程 (Shared Adversarial Review Flow)

适用于阶段一~六。每个阶段在本阶段产物落盘后、宣布完成前执行**一次**；不强制每阶段冗长表格，也不强制额外多轮 agent。

**输入（三者缺一即降级为"未验证"）**：
1. 本阶段实际产物（文件路径 + 关键行/片段，不是描述）；
2. 当前已确认范围（继承的 + 本阶段新增的，含 Non-Goals）；
3. 运行证据（真实命令与其退出码、断言输出、脚本 stdout/stderr）。

**执行顺序**：
1. **确定性检查先跑**：能机械判定的先跑——静态扫描、主键/守恒/有界/NULL 断言、命名契约、六栏完整性、产物存在性。机械检查未跑 ≠ 通过，写"未验证"。
2. **独立 review 后跑**：独立 reviewer 只读审阅（不改产物）。审阅范围 = 实际产物 + 当前确认范围 + 运行证据；**不把未确认事项、专题阈值或阶段外假设算作缺陷**。

**问题记录格式（每条）**：
`严重性 | 证据（文件:行 / 命令+退出码） | 影响（会导致什么错误结论或返工） | 修复（具体动作）`
严重性分三档：`阻断`（结论会错/数据会错/不可复现）、`应修`（影响可维护性或可信度，不阻断）、`提示`（可选改进）。

**闭环**：阻断问题必须修复；修复后**只复查受影响项**，不重跑全量审查。复查结果同样附证据。

**完成门槛登记（每个阶段一行，附 §6 证据指针）**：
```
- [ ] 阶段 N 审查 — 证据: <审查记录位置> — 结果: <阻断 0 / 应修 n / 提示 m；或"未验证: <缺哪项证据>">
```

审查通过 = 阻断项为 0 且证据齐全。**不等于**业务验收或生产上线许可。


## 2. 阶段完成门槛 (Stage Completion Gates)

### 阶段一 (需求收集) 完成门槛
- [ ] 需求 Markdown 落盘于 `01_source_data/`，7 大元数据完整，命名符合契约。
- [ ] 口径交接卡片四要素闭环（Grain / 反事实窗口 / 分母防卫 / 中台关键词）。
- [ ] Non-Goals 与未开展 story 已显式声明。
- [ ] 决策目标可判定（分析驱动哪个管理动作、对比基准是什么）。
- [ ] 阶段一审查（§2.0）：一范围 / 未开展 story / 决策目标。

### 阶段二 (需求分析) 完成门槛
- [ ] 核心事实表/维表物理全称与有效分区已锁定（实测有效分区/快照日，禁止未探查盲目依赖 `MAX_PT`）。
- [ ] 字段权威源与同源单点取值清单已明确（展示与计算判定字段同源，下沉权威维表补齐缺失属性）。
- [ ] NULL/空白/未匹配与 0/负值语义已显式定义（NULL 销量/未命中标记为待核验，不隐式默认补 0 视作无销）。
- [ ] 主键唯一性断言 `COUNT(1)-COUNT(DISTINCT keys)==0` 通过。
- [ ] 6 项基准画像指标已固化（行数、门店数、商品数、主键数、数量总和、金额总和）。
- [ ] 口径锁定卡 (Caliber Lock) 已输出，含 5 大模块。
- [ ] **技术验证**（表/键/基数）已完成并呈现；**业务验证**（时间窗/分母/对照组）已与业务方确认并登记假设日志。
- [ ] 未决项仅剩业务影响确认，无技术阻断。
- [ ] 阶段二审查（§2.0）：节点版本 / 窗口 / 键 / 分母 / 来源优先级。

### 阶段三 (数据方案) 完成门槛
- [ ] RFC 文档与 SQL 文件已生成，命名符合契约。
- [ ] SQL 静态扫描 `0 errors`。
- [ ] 对账守恒门禁已定义（商品数互斥、金额自洽、比率有界、保护不穿透、主键集合金额守恒、NULL 防卫）。
- [ ] 同源判定与原因派生设计已完成（动作标记只计算一次，原因消费该标记，标记与原因双向 100% 互斥闭环；禁止把金额=0擅自混入剔除条件）。
- [ ] 若涉及版本/来源/预测分解：已引用 [EIGHT_CELL_AUDIT_REFERENCE.md](EIGHT_CELL_AUDIT_REFERENCE.md) 并完成八格设计；若涉及目录增删清洗剔除：已引用 [DATA_QUALITY_CHECKLIST.md](../../analytics-data-execution/references/DATA_QUALITY_CHECKLIST.md)。
- [ ] 技术验证（SQL 可执行、分区可解析）与业务验证（目标/Non-Goals/双轨范围）已区分记录。
- [ ] 新店特定流程（双轨范围、90 天考核）仅在新店效益分析分支强制；策略变更分支使用通用范围/影响章节。

### 阶段四 (数据执行) 完成门槛
- [ ] 执行前锁定唯一交付资产身份（既有稳定文件名、外部数据湖真实物理路径、仓库入口软链接）。

- [ ] 技术验证（门禁脚本/SQL 执行）与业务验证（大盘合理性/门店分布）已分离记录。
- [ ] 外部数据湖物理实体与仓库软链接物化完成，完成门槛验证实际物理产物与软链接一致性（杜绝另名生成或假完成）。

## 3. 已确认 / 未决纪律 (Confirmed vs Pending Discipline)

- **继承规则**：阶段 N 不得重新询问阶段 < N 已确认的粒度/分母/时间窗/对照组；仅在本阶段产生变更时重新确认。
- **技术先行**：物理表/分区/键/基数/未匹配处置由分析师自行查证（DMP MCP、实测分区与基准快照探查、画像 SQL），查证后以六栏呈现；不得要求用户提供。
- **业务确认范围**：仅以下内容需用户/业务方确认：指标方向与阈值、策略影响、样本排除的业务理由、对照组选择、交付形态优先级。
- **阻断最小集**：未决阻断时，仅列出无法继续的最小未决集；已可推进部分必须继续推进并交付中间产物。

## 5. 新店特定流程边界 (New-Store-Specific Flow Boundary)

以下流程**仅在新店效益分析分支 (new_store benefit)** 强制：
- 双轨范围 (考核成熟轨 vs 静态备货轨)；
- 90 天考核窗口与 `s_kh`/`e_kh` 动态切分；
- 目录内外品效对决矩阵。

策略变更/缩铺/组货/因果评估分支使用通用"范围与影响"章节，不得被上述新店流程阻断。模板中对应章节标记为 `[NEW-STORE-ONLY]`。

## 6. 证据与完成标准格式 (Evidence & Completion Format)

完成标准必须为可勾选清单 `- [ ]`，每项附证据指针：
```
- [ ] 断言名称 — 证据: <文件/SQL/输出> — 结果: <数值/通过>
```
禁止使用模糊完成语（如"基本完成"、"大致通过"）。

**审查结论的证据要求**：每项必须能追溯到（a）产物文件与行号、（b）真实命令与其退出码或断言输出、（c）复现方式。三者缺一写"未验证"。
**禁止**：用"看起来合理""已通过审查"替代证据；把"文件已生成"当作"已重跑验证"；把"collect-only 通过"（仅收集未执行断言）当作"tests 通过"。
